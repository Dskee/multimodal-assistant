# 智能语音助手（无障碍版）

面向**老年人、行动不便者、听障与聋哑人群**的桌面多模态助手。
以语音为主要交互方式，配一条视觉通道（手势/手语转语音、语音转大字幕），
让「不会用键盘、看不清屏幕、听不清声音、说不出话」这几种情况都有对应的解法。

---

## 一、立项意义

老年人、行动不便者与听障、聋哑人群使用电脑时，卡在同几件事上：**键鼠操作、文字阅读、
语音沟通**。而现有语音助手普遍是"按一下说一句"的命令式交互，既应对不了老年人说话慢、
爱重复、中途改口，也无法在播报中途被打断；聋哑用户更缺少一条"把自己的意思表达出去"
的通道。

本项目做三件事：

1. 把语音交互做成**连续、可打断、可确认**的（而不是一次一问）；
2. 加一条**视觉通道**：手势识别成语音替聋哑用户"说话"，语音转大字幕给听障用户"看"；
3. 全程按**适老化**标准设计：大字号、高对比、文字与语音双通道提示、即时应答音。

---

## 二、三类用户，三条通道

| 用户 | 痛点 | 本项目给的通道 |
|---|---|---|
| 老年人 / 行动不便 | 不会用键鼠、看不清小字 | 语音免手操作 + 慢速播报 + 大字幕 + 指物问答 |
| 听障 / 听力下降 | 听不见对方说话 | **语音 → 大字幕**（置顶大字号，可给对方看） |
| 聋哑 / 言语障碍 | 说不出话 | **手势 → 语音**（识别成短语后读出来给对方听）+ 数字手势 |

## 三、快速开始

```powershell
cd D:\VibeCoding\multimodal_assistant
venv\Scripts\python.exe main.py     # 或双击 run.bat
```

首次使用需要填 API Key：

1. 注册 [硅基流动](https://siliconflow.cn)，创建密钥；
2. 把密钥写进 `config.local.json`：
   ```json
   { "API_KEY": "sk-你的密钥" }
   ```
   （该文件已在 `.gitignore` 中，不会被提交；也支持环境变量 `SILICONFLOW_API_KEY`）

手部模型已随项目放在 `models/hand_landmarker.task`（约 7.5MB）。
若缺失，按程序提示的地址下载即可（该文件被 `.gitignore` 排除）。

## 四、操作手册

### 1. 连续对话（免按键）

1. 点一次 **「开始聆听」**，按钮变成「停止聆听」；
2. 之后**不需要再点任何按钮**：直接说话，说完停顿约 0.8 秒自动断句识别；
3. 回答会**逐句流式播报**（模型产出一句就合成一句并立刻播），不必等全文；
4. **播报中可随时打断**：你一开口就会停止播报并转回聆听；
5. 想结束时点「停止聆听」。

识别成功后、正式回答之前，会先播一句极短的**即时应答音**（"嗯，我看看。"），
让你立刻知道"它听见了"——避免重复说话。

### 2. 大字幕（给听障用户）

- 点 **「打开大字幕窗口」**：独立置顶窗口，黑底白字高对比，可拖到屏幕另一侧给对方看；
- 窗口内 **A+ / A-** 调字号（16~96），或点「字号…」选择；
- 「对方」「我」「系统」三种来源用不同颜色区分，自动滚到最新一条。

### 3. 手势识别（视觉通道）

点 **「开启手势识别」** 打开摄像头；旁边下拉框切换两种用途：

**控制模式**（手势操作程序）

| 手势 | 动作 |
|---|---|
| ✋ 张开手掌 | 开始 / 停止聆听 |
| ✊ 握拳 | 取消当前输入 |
| 👍 拇指向上 | 确认发送（输入框有内容时） |
| 👎 拇指向下 | 停止播报 |
| ✌️ 两指 | 切换字幕模式（开关大字幕窗） |
| 挥手（张开手掌左右摆） | 紧急停止（断开麦克风） |
| ☝️ 食指指 | 指物提问（拍照并读出结果） |

**说话模式**（手势当作"说话"，面向聋哑用户）

| 手势 | 说出的话 |
|---|---|
| ✋ 张开手掌 | 等一下 |
| ✊ 握拳 | 不要 |
| 👍 拇指向上 | 好的，谢谢 |
| 👎 拇指向下 | 我不舒服 |
| ☝️ 食指指 | 我要这个 |
| 数字手势 一/二/三/四/六/八 | 一 / 二 / 三 / 四 / 六 / 八 |

手势需要**稳定保持 0.6 秒**才触发（防抖动误触发），触发后 1.5 秒内不重复。

### 4. 指物问答

点「拍照」或做 ☝️ 手势 → 自动问「这是什么」→ 视觉模型识别 →
**结果语音报出**（可在界面取消勾选只显示不朗读）。

### 5. 确认式交互（关键信息必复述）

识别结果里含**用药、金额、时间、密码**等关键词时，程序会先复述一遍：

```
你：这个药一天吃几次
它：您是说：这个药一天吃几次，对吗？
你：对          → 按识别结果正常回答
你：不对        → "好的，请您再说一次"
（20 秒没答复，或说了别的事 → 当作新的一句话处理）
```

这条规则来自实测：ASR 会把「这个药」听成「这个要」，用药场景不能靠猜。

### 6. 免手操作电脑（本地指令，不经过大模型）

这些指令由**本地规则**直接执行并立刻回答，实测**界面出现回答约 20 毫秒**
（对比走云端一轮需要数秒到十几秒）：

| 说 | 效果 |
|---|---|
| 声音大一点 / 小一点 / 静音 / 取消静音 | 调节系统音量 |
| 打开记事本 / 计算器 / 画图 / 写字板 / 文件管理器 | 打开白名单里的程序 |
| 打开百度 / 淘宝 / 京东 | 用默认浏览器打开常用网站 |
| 记一下 明天早上八点吃降压药 | 记进待办（本地文件） |
| 读一下待办 | 读出最近几条；说「清空记事」可清空 |
| 剪贴板里是什么 | 读出剪贴板内容 |
| 读一下屏幕上的字 | 截屏后交给视觉模型读出屏幕文字并朗读 |
| 现在几点 / 今天几号 / 今天星期几 | 本地时间（不联网、不用模型） |
| 你能做什么 | 列出上面这些能力 |

**安全设计**：打开程序走**白名单**，不在表里的名字一律拒绝执行并说明——
绝不把模型输出直接当成命令去跑（自检里验证过：连
`打开 C:\Windows\System32\cmd.exe` 也会被拒绝）。要加自己的程序，改
`config.COMMAND_APP_WHITELIST` 即可。

### 7. 日志与记忆（可以当日志助手用）

把说过的话记下来，并在之后的对话里用得上：

| 说 | 效果 |
|---|---|
| 记一下 今天血压 130/85 | 带时间记成**日志**（可回看、可检索） |
| 记住 我女儿叫小芳 | 记成**关于我的长期事实**，之后问起它能答上来 |
| 读一下记事 | 读出最近几条日志 |
| 今天记了什么 / 昨天记了什么 / 这周记了什么 | 按日期回看（说「聊了什么」则回看对话记录） |
| 查一下 血压 / 还记得 医院 | 关键词检索历史记录 |
| 记了多少条 | 看统计（日志 / 事实 / 对话各多少条） |
| 清空记事 / 清空记忆 | 清空（前者保留事实与对话，后者全清） |

**两个设计要点**（简历上可以讲）：

1. **"日志"和"长期事实"分开存**：事实每轮对话都会注入大模型（所以「我女儿叫什么」
   一问就答得上来），日志只在**相关时**才检索出来。若把事实当日志存，
   问起时不一定想得起来。
2. **检索用字符二元组重合度 + 口语停用词**：中文不需要分词器，十几个字的短句够用，
   而且打分可解释。踩过的坑：一开始没有停用词表，问「今天**天气**怎么样」时
   "今天"撞上了记录「**今天**血压 130/85」，1/6 的重合度刚好越过阈值，
   把无关的血压记录也注入了——加上停用词表后该次注入变成 0 命中，
   而「我上次血压多少」仍能靠"血压"命中：**抓的是内容词，不是寒暄词**。

界面上有「查看日志」按钮（可按日期/类型浏览，并能直接打开文件所在文件夹）。
**全部内容只存在本机 `data/memory.json`，不上传、不联网、不依赖向量数据库。**

### 8. 点「参数说明」看当前生效的语音参数

断句静音时长、打断灵敏度、即时应答音等。这些参数在采集线程启动时就已生效，
改它们需要编辑 `config.py` 后重启，因此界面上只做透明展示，不放可编辑控件
（否则会让人以为改了却没变）。

## 五、技术路线

```
麦克风 ─┐
        ├─→ VAD 自动断句 ─→ ASR（带超时重试）─→ 大模型流式 ─→ 分句流式播报 ─→ 扬声器
回环   ─┘        ↑                                              ↑
（WASAPI）   回声消除（NLMS）                              播报中打断检测
摄像头 ─→ 手部 21 关键点 ─→ 手势分类 ─→ 控制动作 / 手势说话
```

| 环节 | 实现 | 关键实测数据 |
|---|---|---|
| 断句 | webrtcvad 帧级语音活动检测 + 首尾 padding + 尾静音裁剪 | 自检切句 1620ms（期望 1600ms） |
| 回声消除 | 块 NLMS 自适应滤波，用 WASAPI 回环作参考信号 | 收敛后 **ERLE 10.0 dB**，回声残差 0.00018 vs 插话 0.0234（130 倍） |
| 打断检测 | 能量比 + 本底自适应（只在非语音帧更新）+ 带泄漏累加器 + 语音门控 | 回声段比值 0.82 / 插话段 170.67，触发延迟约 260ms，误触发 0 |
| 识别 | SenseVoiceSmall（硅基流动） | 真实录音识别准确；稳态 0.2~0.4 秒，实测抖动到过 **14 秒、18.6 秒**（故设 20 秒超时 + 重试） |
| 对话 | Qwen2.5-7B-Instruct（OpenAI 兼容） | 首 token **294 ms**；关闭推理模型思考模式后首字 37s → 0.79s |
| 播报 | edge-tts 本地合成 + pygame 播放，**分句流式** | 首句一出来就出声，不必等全文 |
| 手势 | MediaPipe HandLandmarker + 几何规则分类 | 模型加载 0.25s、**单帧 12ms**（实时要求 <100ms） |
| 记忆/日志 | 本地 JSON + 字符二元组检索（含口语停用词） | 纯本地不上传；事实恒注入、日志仅相关时注入 |
| 本地指令 | 正则规则路由 + 程序白名单 | 实测**界面响应约 20ms**（走云端一轮是数秒到十几秒） |
| 界面 | PyQt5 桌面原生，QThread/QTimer 保证不卡界面 | 引擎回调经 Qt 信号排队回界面线程 |

**依赖**：PyQt5、pyaudio、pyaudiowpatch（回环）、webrtcvad-wheels、mediapipe、
openai、edge-tts、pygame、opencv、numpy。

- 手势 → 界面动作分发（✌️ 能开关大字幕窗）
- 记忆模块自检：写入/持久化/按日期/按关键词检索/清空分类保留、

## 七、已知边界（写进答辩口径）

1. **手语**：完整手语是"手形 + 位置 + 运动 + 面部表情"的语法系统，全量识别属研究级难题。
   本项目做的是**受限词表的静态手势**（外加"挥手"一种运动手势）。
   第六节的词表是**本项目定义的简化手势**，不等同中国手语（CSL）的标准打法；
   要做到标准手语需要带时序标注的数据集与训练模型。这一点在代码注释里也标注了。
2. **数字手势**：一/二/三/四/五/六/八 可靠识别；**七、九、十**依赖更细的指节弯曲与
   三维姿态，当前不支持（宁可说"不支持"，也不装作能识别）。
3. **ASR 延迟抖动**：云端识别稳态 0.2~0.4 秒，但实测出现过 **14 秒、18.6 秒**
   （4.4 秒的录音）这样的极端值。系统按"预热 → 超时重试 → 降级提示重说"三层兜底，
   并且**即时应答音放在识别之前**播——早期版本放在识别之后，
   结果用户要对着空气干等十几秒，安抚作用完全失效（整体联调时才暴露出来）。
4. **回声消除的前提**：需要"系统正在播放什么"作为参考信号。
   戴耳机时不存在回声路径，程序会自动判定为"无回声"并改用语音门控的打断检测。
5. **分句播报目前是顺序合成**：下一句要等当前句播完才开始合成，
   实测多句回复每句约多花 2~3 秒。已列入下一步优化（预合成下一句，
   与当前句播放重叠），当前不影响正确性。
6. **唤醒词未实现**：`config.WAKE_WORD_ENABLED` 与 openwakeword 依赖已就位，
   但**尚无任何调用方**，属规划中功能，当前靠「开始聆听」按钮开启，
   麦克风在点击之前不会打开。

## 九、调试与常见问题

| 现象 | 怎么查 |
|---|---|
| 没有听清 / 识别不准 | 点「设备自检」看麦克风采集是否正常；环境噪声大时说话靠近麦克风 |
| 播报时它自己误判被打断 | 确认回环设备与**默认输出设备**配对（本机曾取错设备）；戴耳机时应自动判为无回声 |
| 手势没反应 | 手势需保持 0.6 秒；确认摄像头未被占用；看「最近手势」是否显示识别结果 |
| 开始聆听失败 | 麦克风被其他程序占用；或先用「打字输入」通道（无需麦克风） |
| 首字很慢 | 查看是否用了推理模型（需关闭思考模式）；即时应答音会先出声掩盖等待 |

每个核心模块都能**单独自检**（不需要启动界面）：

```powershell
venv\Scripts\python.exe -m core.audio_input            # 断句/回声/打断算法
```
